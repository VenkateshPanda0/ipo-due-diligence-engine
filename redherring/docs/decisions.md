## D-003 — PDF stack: pdfplumber + pypdfium2; no PyMuPDF (2026-10-19)

pdfplumber for word geometry and table finding; pypdfium2 for per-page text-layer/image checks.
Both permissive (MIT/BSD/Apache-2.0-class); PyMuPDF is AGPL and would constrain a permissive
release of this project. Cost: pdfplumber (pure Python) is slow on 500+ page documents; measured in
the M0 parse report and parallelisable per page range if needed.

## D-004 — Standard library for HTTP and CLI in M0 (2026-10-19)

## D-006 — Page and unit model (2026-10-19)

- Every block/table carries a 1-based `pdf_page` (physical page). The printed page label is stored
  separately as `printed_page`, best-effort, and is never used for citations.
- Downstream text is rendered with parser-injected `[PDF_PAGE_N]` tags; page numbers are never
  inferred from page text.
- Units (rupees, thousand, lakh, million, crore, billion) are detected per table from the caption
  above it or its first rows, and stored on the table with the matched text. Values are not
  converted in M0. Conversion helper `to_rupees` exists and is tested.
- No OCR in M0. Pages with no text layer but with images are flagged `needs_ocr` and reported.

## D-011 — Fetcher integrity rules, from real downloads (2026-10-21)

Both SEBI PDFs were silently truncated by the first fetcher. Rules now: compare received bytes with
the announced length, resume with HTTP Range (bounded retries, restart if the server ignores Range),
require `%%EOF`, and treat a cached file that fails these checks as missing. Alternative considered:
trusting the manifest hash alone; rejected, because a hash of a truncated file is still a valid hash.

## D-012 — Never flip table orientation silently (2026-10-21)

Orientation detection flagged 63 tables in one document and the sampled ones did not look like
correct flips. Rows are kept as found with a `transposed_suspect` flag; flipping is an explicit
`tables.transpose` call, to be enabled only if labelled data shows the detector is precise.
Parsed output carries `parser_version` so stale cached output is never reused.

## D-015 — Rules are TOML specs with validity windows (2026-10-23)

Each rule is a data file naming its logic type, thresholds, platforms, `valid_from`/`valid_to`,
and its sources (ICDR clause, effective date, date checked against SEBI's consolidated copy
"Amended upto March 21, 2026"). A superseded threshold is kept as a separate `-PRE2025` rule so a
2024 filing is judged by 2024 law. Heuristic rules say so and cite the literature. Alternative
considered: thresholds in Python; rejected because the audit trail (clause + date) must live next
to the number.

## D-016 — Label-free correctness checks come first (2026-10-23)

Because hand labels are scarce, three checks need none and run on every document: (1) each cited
value is re-read from the PDF text layer through a different code path; (2) accounting identities
foot (total income = revenue + other income; PAT = PBT - tax; assets = equity + liabilities);
(3) independent tables agree (consensus). A value that fails (1) is never reported. (2) and (3)
are signals, not proof; the benchmark (D-018) is the measurement.

## D-017 — Consensus prefers columns that foot (2026-10-24)

Repetition is not evidence: three cash-flow tables printing "profit before tax" before the share
of an associate (2,239.30) outvoted the P&L's 2,239.15. Readings from (table, period) columns whose
own identities foot are preferred to any number of readings from columns that cannot be checked;
trust is per column because one year printed with a different sign convention must not discredit
the years that foot. Within an agreeing cluster the exact figure most tables print is reported.

## D-018 — Benchmark scoring and its honest limits (2026-10-24)

A prediction is correct when it is within the coarser printed precision of the label (so 538.02
vs 538.03 agree, 2,239.30 vs 2,239.15 do not). Citation accuracy requires the cited page to be one
where the labeller found the statement. Labels were written by the maintainer, an AI, reading
poppler text (a different extraction path); there is no inter-annotator agreement. The first six
filings are a development set: the extractor was tuned against them, so their scores overstate
generalisation. A held-out set (D-021) was added to measure that.

## D-019 — No LLM key in this environment (2026-10-23)

No API key exists in the sandbox, so the LLM layer (provider protocol, hard cost cap enforced
before each call, on-disk cache, validated structured output, untrusted-document prompts) is built
and tested against a fake provider only. No LLM number is claimed. Everything that ships works
without it; the LLM is for the long tail the deterministic extractors miss.

## D-022 — The report is one self-contained HTML page (2026-10-24)

`rh report` writes one page per filing: flags with evidence, issue and objects, annual figures in
₹ crore, what could not be checked, figures withheld because tables disagree, how far to trust the
extraction. No script, no external resource; every figure links to `#page=N` of the source PDF; all
text from the document is HTML-escaped (tested with hostile input). "No flags" is worded as "not a
clean bill of health" with the count of rules that could be evaluated, because zero flags is mostly
missing inputs. Rules that never applied (other platform, not yet in force) are collapsed so they
do not read as gaps.

## D-023 — Rules that do not fit a business are not applied (2026-10-24)

The cash-flow-below-profit heuristic fired on a lender and a developer, for whom negative operating
cash flow is structural (loan book, inventory). A rule may list `not_for_sectors`; sectors come from
counting self-description in the first 150 pages (lender: NBFC / housing finance wording at least
30 times; real estate: RERA / project wording at least 30 times). Thresholds were set on nine
filings (lenders 61 and 126 mentions, a payments company 15, a developer 9 NBFC mentions). The
exclusion is shown in the report and the rule audit as "not applied to this kind of business".

## D-024 — ICDR 2018 rules start on 10 Nov 2018 (2026-10-24)

A December 2005 draft was being judged by 2018 thresholds because several rule files had no start
date. They now start when the regulations came into force (gazette 11 Sep 2018 plus 60 days; the
consolidated SEBI copy omits the date, so it rests on secondary sources, noted in each rule file).
Rules for periods before that are not written: the predecessor regulations (2009) are a separate
primary text that has not been read.

## D-027 — Text a reader cannot see (2026-10-24)

The text layer is what the extractor reads, but a reader sees what is drawn. Characters under one
point or wholly off the page are dropped; white characters with no coloured shape, curve or image
behind them are kept (white on a coloured header is normal) and counted. A page with 15 or more
such characters, or any dropped, is "hidden-text": the report warns, cites of it carry a mark, and
any fact whose every citation is on such a page stays out of the rules. The 15-character floor and
the curve/image test come from sampling nine pages where a first, rectangle-only version flagged
chart labels and arrows. Full model in `docs/security.md`.

## D-028 — A captionless statement may borrow a sibling's unit (2026-10-24)

Indong Tea prints "(Amount Rs. In Lakh)" over the balance sheet and income statement but not the
cash-flow statement, so its figures could never be converted or compared. A statement without a
unit takes the unit of tables within two pages whose columns name exactly the same period dates,
only if all such tables agree and never from a table that itself borrowed; the page is recorded in
`unit_inherited_from`. A wrong scale would be worse than none, hence the three conditions. It also
raised the share of tables with a unit from about 34% to 45% on the nine older filings.

## D-029 — Diff compares figures, not prose, and ignores periods only one side has (2026-10-24)

`rh diff` compares the facts the rules can use, within the coarser printed precision, so a
restatement appears and re-rounding does not. A financial figure for a period only one version
contains (a new six-month stub, a year that left the window) is listed in one line, not as 40
"removed/added" rows: the first version of the diff drowned the two real changes (issue size cut
from 8,500 to 7,000 million) in them. Issue and objects keys that appear or vanish do count. Empty
placeholder packages (`diff`, `report`, `research`) from the first skeleton were deleted because
`redherring/diff/` shadowed the new `diff.py`.

## D-031 — Figures under misaligned headers (2026-10-26)

Ruled tables with spacer columns can print right-aligned figures up to two cells left of
left-aligned "As at ..." headers, and rows differ among themselves. A figure column with no dated
header takes the nearest dated header within two cells (the right one on a tie). Where figures sit
under their headers, behaviour is unchanged (tested). Residual risk: an unlabelled numeric column
within two cells of a dated header (a blank-headed percentage column) would be given that period.

## D-032 — Debt repayment share of the fresh issue, as a low-severity heuristic (2026-10-26)

New fact `objects.debt_repayment_amount`: the objects-table rows whose label is a repayment or
prepayment of borrowings, summed (unless one row already totals the others; a repayment made
through a subsidiary counts), and a heuristic rule that flags more than 50% of the gross fresh
issue at severity low (new `over_cap_severity`; a regulatory breach stays high). Across the
filings, LEAP India (75%), Powerica (75%) and Runwal (65%, of which 2,250 million is repayment
through two subsidiaries) are flagged; Indiqube (14%), Synoptics (14%), Shiprocket (19%) are not.
Not a regulatory limit, and repaying debt can be sensible: the flag says so in its basis. A
summed fact is verified part by part against the page (`IssueFact.parts`); a lone "repayment"
line and its "Total", or negative cash-flow lines, no longer qualify a table as an objects table.
No labels exist for this fact yet; they belong in the next held-out set.

## D-033 — Position and entity awareness in extraction and consensus (2026-10-27)

Held-out run 4 (`docs/heldout-run-4.md`, first run 54%) showed that repetition is a poor proxy for
correctness in 1,000-page filings. Decisions: (1) cover-table amounts are read by column position,
not order of appearance; (2) consensus weights front-of-document readings double, gives readings
under entity-qualified headers (excluding, standalone, subsidiary, segment, pro forma) weight 0,
and lets trusted columns be corroborated by agreeing untrusted ones; (3) a figure is kept on a
weighted lead of at least 2x, or, for size concepts only, a narrower lead when it is also the
largest figure; (4) kerned labels ("T otal") are repaired before matching. Cost: a genuine
subsidiary-only figure under a header that happens to say "subsidiary" is down-weighted, and the
front-weight assumes the issuer's own figures come first; both were true for all 18 filings but
that is a small sample. Abstention is preferred where definitions conflict (Tata Capital's PAT).

## D-034 — Bare-year headers, net operating cash flow, stub columns (2026-10-28)

Held-out run 5 (`docs/heldout-run-5.md`). (1) A header that is only a year takes the wording of
the dated header beside it, left first; never from an annual header across a quarter, which would
turn "June 2024" into a fiscal year. (2) A table that has a "net cash ... operating activities"
line ignores the "cash generated from operating activities" pre-tax subtotal. (3) A blank-headed
figure column left of the first dated header, beside a dated header column that holds figures,
stays undated. The broader rule I tried first (never lend a header to a column whose own header
column holds figures) cost two correct Veritas readings and was reverted: a blank column that
borrows a neighbour's header always produces a second reading for that period in the same table,
which is dropped as ambiguous, so the failure mode is abstention, not a wrong value. (4) Labels:
a label whose field is absent must be re-read on the cover and the summary pages before commit
(two label errors this run). Residual risk: a bare year after an unrelated dated header cell
inherits its wording.

## D-035 — Label column and dateless captions (2026-10-28)

Held-out run 6 (`docs/heldout-run-6.md`). The label column is searched among the first five cells
(was three): numeric columns never qualify, so the cost of a wider search is nil, and statements
with a serial, two blank cells and then the label are common in financial-services filings. A
dateless header cell over figures borrows the dated header in the next cell only if that dated
column holds no figures of its own; where the dated header has figures it is left alone. Residual
risk: a genuine undated column immediately left of an empty dated column would be given that date.

## D-036 — Placements are not the offer (2026-10-29)

Held-out run 7 (`docs/heldout-run-7.md`). The text patterns for the fresh issue and offer for sale
amounts may not read across "pre-IPO" or "private placement" wording: in a glossary that runs on
without sentence breaks, the placement's amount was taken as the offer for sale and then summed
into a derived total. Residual risk: other raises mentioned beside the offer (a rights issue, a
bonus) are not yet excluded; the cover-table reader, which does not use these patterns, takes
precedence where it applies.

## D-037 — A set that causes no code change stays held out (2026-10-30)

Held-out set 8 (`docs/heldout-run-8.md`) was read correctly on the first run except for one value
that was my labelling error. With no extractor change to make, the set was not turned into
development data: its numbers still describe the shipped code, so it is a clean baseline for the
next change. The rule is now: a set becomes development data when, and only when, a defect it
exposed is fixed. Label corrections do not count.
